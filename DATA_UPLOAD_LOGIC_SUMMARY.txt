SPREADSHEET DATA UPLOAD FUNCTIONALITY - LOGIC SUMMARY
==================================================

OVERVIEW
--------
The admin panel provides comprehensive spreadsheet upload functionality for processing taxonomic observation data from multiple sources (iNaturalist, Mushroom Observer, sequence databases). The system handles Excel files (.xlsx/.xls) up to 50MB with robust processing, validation, and batch insertion capabilities.

FRONTEND COMPONENTS
------------------

1. FileUpload Component (client/src/components/admin/FileUpload.tsx)
   - Drag-and-drop interface with visual feedback
   - File validation (Excel formats only, 50MB max)
   - Upload progress tracking with phases: idle → uploading → processing
   - Real-time progress bar and status updates
   - Error handling with user-friendly messages

2. AdminUpload Page (client/src/pages/admin/AdminUpload.tsx)
   - Main upload interface with card layout
   - Integration with FileUpload component
   - Upload history and processing status monitoring

3. AdminModal Component (client/src/components/admin/AdminModal.tsx)
   - Modal interface containing FileUpload, UploadHistory, ProcessingStatus
   - Red List management integration
   - Responsive grid layout

BACKEND PROCESSING PIPELINE
---------------------------

1. Upload Endpoint (POST /api/upload)
   - Uses multer middleware for file handling
   - Creates upload record in database with 'processing' status
   - Initiates background processing via processExcelFile()
   - Returns upload ID for progress tracking

2. File Processing (processExcelFile function)
   
   a) INITIALIZATION PHASE
      - Validates file exists at specified path
      - Clears existing data to prevent duplicates
      - Dynamically imports XLSX library
      - Reads workbook and identifies target worksheet
   
   b) WORKSHEET SELECTION
      - Prioritizes sheets containing 'validated' or 'observation' in name
      - Falls back to first sheet if no match found
      - Converts sheet to JSON format for processing
   
   c) COLUMN MAPPING & ANALYSIS
      - Maps 47 specific fields from Excel columns
      - Logs available vs mapped vs unmapped columns
      - Tracks field coverage for debugging
   
   d) DATA TRANSFORMATION
      - Constructs scientific names using taxonomic hierarchy:
        Priority: Variety → Species → Genus → Family → Order → Class → Phylum → Kingdom
      - Handles date conversions (Excel serial dates, Date objects, strings)
      - Processes coordinates (latitude/longitude as strings)
      - Maps all 47 fields including sequences, primers, specimen data
   
   e) VALIDATION FLAGS
      - name_update: Species or Variety missing
      - classification_update: Has species/variety but missing higher taxonomy
      - Counts and logs validation flag statistics

3. Batch Insertion System
   - Processes records in batches of 500 for stability
   - Enhanced monitoring with timing and memory usage
   - Progress milestones every 2,500 records
   - Error handling with detailed batch information
   - 50ms delays between batches to prevent database overload

4. Post-Processing Phase
   - Updates contributor statistics
   - Updates species statistics  
   - Builds GPS index for map performance
   - Runs automated classification updates
   - Updates upload status to 'completed' or 'failed'

FIELD MAPPING (47 TOTAL FIELDS)
-------------------------------

Core Taxonomic Fields:
- Kingdom, Phylum, Class, Order, Family, Genus, Species, Variety
- Authority, Abbreviated Authority, Mycobank #

Identification & Collection:
- Reference Number, Collection Number, Collector, Sequence Owner
- Report Date, Creation Date, Verified

Location Data:
- Location Name, Country, City, State, Latitude, Longitude

Genetic & Sequence Data:
- GenBank Accession #, MyCoPortal #, DNA Sequence, Sequence
- Forward/Reverse Primers, Run Name, Sequence Owner
- Secondary sequence data (Sequence #2, primers, etc.)

Specimen & Documentation:
- Fungarium Specimen, Images, Image Link, Report Link
- Notes, MO Notes, Flags

Source & Validation:
- Source Database, First State Record, First GenBank Record
- Multiple Genotypes Under Name

AUTOMATED CLASSIFICATION UPDATES
--------------------------------
- Matches records with missing higher taxonomy to complete records
- Uses genus-level matching to populate Kingdom → Family hierarchy
- Runs automatically after upload completion
- Manual trigger available via API endpoint

ERROR HANDLING & MONITORING
---------------------------
- Comprehensive logging at each processing phase
- Memory usage monitoring during batch processing
- Detailed error messages with context
- Upload status tracking (processing/completed/failed)
- Progress reporting with timing metrics

PERFORMANCE OPTIMIZATIONS
-------------------------
- Batch processing prevents memory overflow
- GPS index building for map performance
- Streaming file reads for large files
- Database connection pooling
- Progress milestones for long-running operations

API ENDPOINTS
------------
- POST /api/upload - File upload initiation
- GET /api/uploads - Upload history and status
- POST /api/reprocess/:id - Reprocess existing upload
- POST /api/auto-populate-classification-updates - Manual classification update trigger

VALIDATION & QUALITY CONTROL
----------------------------
- File type validation (Excel only)
- File size limits (50MB max)
- Scientific name construction validation
- Date format normalization
- Coordinate validation
- Duplicate prevention via data clearing

SUPPORTED DATA SOURCES
---------------------
- iNaturalist observations
- Mushroom Observer records
- Sequence database exports
- Custom taxonomic datasets

This system provides robust, scalable processing of large taxonomic datasets with comprehensive error handling, progress monitoring, and automated data enhancement capabilities.
